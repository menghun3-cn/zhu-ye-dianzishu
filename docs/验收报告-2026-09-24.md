## 五、本轮验收发现并修复的缺陷

验收过程中抓到 4 个真实缺陷，均已修复并回归通过：

| # | 严重度 | 问题 | 根因 | 修复 |
| --- | --- | --- | --- | --- |
| 1 | **严重（白屏）** | 打开书没有正文，一片空白 | 底栏 `Slider` 无高度约束：`Slider.computeDryLayout` 在高度有界时返回 `constraints.maxHeight`，而 Scaffold 给 `bottomNavigationBar` 的高度约束是"松到整屏"，于是底栏被撑满整屏，正文区被压成 0 px | 底栏改为 `ColoredBox + SizedBox(height: 52)` 固定高度，Slider 外套 `SizedBox(height: 36)`；页码额外做 `clamp` 防越界 |
| 2 | **严重** | 阅读页点按 / 滑动全都不翻页，点中间也不切工具栏 | `SelectionArea` 内层 Tap/Pan 识别器在手势竞技场中抢走所有手势 | 改用 `Listener`（原始指针事件，不参与竞技场）+ `PageView` 关掉自身滚动（`NeverScrollableScrollPhysics`），自行判定点按/拖动 |
| 3 | 功能 | 书签**删不掉**（点了还在） | `toggleBookmark` 先 `removeWhere` 再判断 `isBookmarked`——此时已被删，判断恒为 false，于是又加回来 | 先记 `existed` 再删，`if (!existed) add` |
| 4 | 体验 | 分类筛选条里「全部」不在第一位，被中文分类挤到后面 | 生成 chip 列表时对整体做了 `sort()`，中文分类按码点排在「全部」之前 | 改为 `['全部', ...排序后的分类]` |

此外，为让验收测试可稳定运行（widget test 走**假时钟**），做了两处测试友好改造：

## 九、追加（15:37–15:50）：PC 端快速切换章节 + 分页测量一致性修复

用户问「pc端如何快速切换章节」。原先只有「底栏目录抽屉里点」和「翻到章末点下一章」两条路，
PC 上没有任何键盘快捷键，长书（实测 245 章）在抽屉里找章得手滚。补齐四件事：

### 1. 键盘快捷键（新增能力，`reader.dart`）

| 按键 | 动作 |
| --- | --- |
| `←` / `PageUp` | 上一页（已在章首再按 → 退到上一章最后一页） |
| `→` / `PageDown` / `空格` | 下一页（已在章末再按 → 进下一章） |
| `Ctrl + ←`（或 `[` / `p`） | 上一章（落在该章开头） |
| `Ctrl + →`（或 `]` / `n`） | 下一章（落在该章开头） |
| `Home` / `End` | 本章第一页 / 最后一页 |
| `Ctrl + Home` / `Ctrl + End` | 全书第一章 / 最后一章 |
| `Esc` | 关目录抽屉 / 收起工具栏 |

实现要点：`build()` 拆成 `Focus(...) → _buildScaffold()`，在**最外层**收键盘事件
（正文被 `SelectionArea` 包着，它只处理复制/全选，其余键沿焦点链冒泡上来；而 AppBar 按钮与 body 是兄弟节点，
只包 body 会漏掉"点过 AppBar 按钮之后按方向键"的场景）。修饰键读
`HardwareKeyboard.instance.isControlPressed || isMetaPressed`。

### 2. 目录抽屉自动定位到当前章

列表改为固定行高（`itemExtent: 44`）+ `ScrollController`，`_openToc()` 打开后把当前章滚到眼前。
245 章的书手滚不动，这一步是刚需。

### 3. 底栏加「上一章 / 下一章」按钮

给不走键盘的路径一键直达（`visualDensity: compact`，不挤占滑条）。

### 4. 顺手修掉一个真缺陷：分页测量与渲染不一致 → 页底文字被静默裁掉

新增的键盘用例逐页渲染时抓到 `A RenderFlex overflowed by 23 pixels`（正文 Column）。
根因是分页引擎量高度与实际渲染有四处不一致：

| # | 测量侧 | 渲染侧 | 处置 |
| --- | --- | --- | --- |
| 7 | `TextPainter` 未设 `textAlign` | `Text.rich(..., TextAlign.justify)` | 测量侧补上 `justify`（断行位置才一致） |
| 8 | `Divider` 按 28px | `Padding(v:14)` + Divider 自带 16px = **44px** | 改成 44 |
| 9 | 列表项宽度扣 `1.2×fs` | `Row['·  ', Expanded]`：实际扣约 `1.7×fs` | 改成 `1.8×fs` |
| 10 | 引用宽度扣 `2.0×fs` | `Padding(l:1.0×fs, r:0.5×fs)` | 改成 `1.5×fs` |

另加 `avail = height − fontSize × 0.4` 的安全余量，兜住字体度量差异（宁可每页少排小半行，也不裁字）。
副作用是页码变多：全库 54 本 69,748 → **70,991** 页，属预期。

## 十、追加（16:00）：阅读页没有返回入口（用户反馈「没法跳到首页」）

### 现象
用户实机反馈：进了阅读页以后回不到书架/首页。

### 根因（框架默认行为导致的整块功能缺失）
`reader.dart` 的 `Scaffold` 设了 `drawer`。**Flutter 的 `AppBar` 在 `leading` 为空且 Scaffold 有 drawer 时，
会自动把 leading 换成「打开抽屉」的汉堡按钮** —— 于是「返回」这个位置被「目录」占了，
整个阅读页上没有任何返回入口，只剩 Windows 窗口右上角的关闭按钮（那是退出整个应用）。

### 修复
| # | 改动 | 位置 |
| --- | --- | --- |
| 1 | `AppBar.leading` 显式给返回按钮（tooltip「返回上一页（Alt + ←）」）；目录改由底栏「目录」按钮打开（Esc 可关） | `reader.dart` `_buildScaffold` |
| 2 | 新增 `Alt + ←` 快捷键返回（与资源管理器/浏览器的「后退」一致） | `reader.dart` `_onKey` |
| 3 | 目录抽屉顶部加「返回上一页」项（打开抽屉的人多半想离开这一章） | `reader.dart` `_buildTocDrawer` |
| 4 | 章节项加稳定 key `toc-<i>`，验收测试改按 key 定位（不再依赖「第 N 个 ListTile」） | `reader.dart` / `acceptance_ui_test.dart` |

`_backToShelf()` 先 `_save()` 落盘阅读进度，再 `canPop()` 判定后 `pop()`；被当根路由挂载（深链/测试）时无路可退也不会抛异常。

### 2. 本轮抓出并修复的 2 个真缺陷

| # | 严重度 | 问题 | 根因 | 修复 |
| --- | --- | --- | --- | --- |
| 11 | **严重（崩溃）** | 退出阅读页偶发 `setState() called when widget tree was locked` | `ReaderPage.dispose()` 里调 `_save()` → `Store.setProgress` → `notifyListeners()` → `HomeShell.setState()`，而此时正在卸载、树被锁 | `setProgress(..., {bool notify = true})` 加静默开关；`dispose()` 用 `_save(notify: false)`，落盘照旧但不广播 |
| 12 | **严重（页底静默裁字）** | 部分书部分页报 `RenderFlex overflowed by 34 / 23 / 19 pixels`，真机表现为页底那行被裁掉 | 分页引擎量高度用「裸样式」，而渲染侧 `Text.rich` 会合并 **Material 3 的 `DefaultTextStyle`（`bodyMedium`：`letterSpacing: 0.25`、`height: 1.43`）** → 断行数不同、多出一行 | ① 在 `_PageContent` 里**显式钉住** `DefaultTextStyle`（`letterSpacing/wordSpacing = 0`、`height` 归一到排版参数）；② 把「块 → InlineSpan」抽成**同一个** `blockSpan(block, typo)`，测量与渲染共用；③ `TextScaler` 一路透传（`MediaQuery.textScalerOf` → `Paginator`），系统字体缩放也一致 |

### 3. 新增一条**永久回归**：`test/pagination_render_parity_test.dart`（2 用例）

这是针对缺陷 #12 的防复发闸门——**它不靠人工比对，而是把分页结果真渲染出来**：

- 合成边界块（列表项 / 引用 / 分隔线 / 代码块 / 各级标题 / 5000 字超长块切页 + 混排）；
- 真实书包 3 本 × 落地章起 3 章；
- 对**分页后的每一页**调用 `buildPageContentForTest()` 真实渲染，任何 `RenderFlex` 溢出都会让用例异常失败。

> 关键点：`@visibleForTesting buildPageContentForTest(...)` 这个钩子让测试能渲染「与线上同一条渲染路径」，
> 而不是另写一份断言逻辑——否则又是一次「测量/渲染各写一份、迟早漂移」。

### 4. 测试脚手架修正（不是产品 bug，但不修测不准）

| 现象 | 真相 | 修法 |
| --- | --- | --- |
| 阅读页在测试里整体偏移 +222px，点击全部落空 | **不是产品 bug**：`pumpAndSettle` 本身能把 `MaterialPageRoute` 滑动转场跑完（实测 AppBar L=0.0），但转场进行中插入 `runAsync`（等书 IO）会让转场**停在半途** | 测试里用 `PageTransitionsTheme` + 空 `PageTransitionsBuilder` 关掉转场；每次 `openReader` 前 `resetTree()`（先 pump 一个 `SizedBox.shrink()` 清空 Navigator 路由栈） |
| 第二次 `openReader` 点「书架占位页」失败 | `pumpWidget` 复用同一个 `MaterialApp`/Navigator，上一轮 push 的路由还在栈里 | 同上 `resetTree()` |
| C12–C16「章末继续点右没进下一章」（期望 4 实到 3） | **样本不满足场景前置条件**：所选书只有 3 章，该用例要连跨两章，物理上不可能 | 样本选择器加约束 `land + 2 < 章节数`；键盘用例样本要求 `章数 ≥ 8 且落地章页数 ≥ 3` |
| C20–C25 找不到 `toc-2` | 目录是 `ListView.builder` 懒构建 + 打开时自动定位到当前章，目标项尚未构建 | 先 `tocToTop()` 把目录滚到顶部再按 key 点 |
| C26–C29 书签摘录 `contains` 失败 | 跨块拼接处空白字符差异 | 两侧先做空白折叠再比对 |
