## ⚠️ 上文事实更正（同日实测推翻，以此节为准）

上文第 2 条「实测 13,645 条」「`link` 指向网盘、**批量自动化下载不可行**」「有验证码/登录/限速」**全部是错的**，那是基于页面静态分析的误判 + 一次错误的正则计数。用户当时质疑，我实测后确认**用户是对的**。更正如下：

**名录**：`all-books.json` 实际 7,132,158 字节，`entry_count = 24,071`（每条都有全部 7 个字段，无缺失）。`language` 全为 `ZH`，`level` 全为 `Unknown`，`category` 有 **1,000 种**（Top: 文学 2711 / 历史 1748 / 科普 743 / 管理 613 / 社会 558）。`formats` 三条目**都是 [epub, mobi, azw3]**（24,071 条全部含 epub，0 条缺）。有效 ctfile 链接 24,002 条，其中 69 条是占位符「链接未找到」；**去重后只有 11,348 个不同书包**（同名同作者重复对 8,911 组，如《与机器赛跑》重复 6 次）。

**下载链路（已完整打通并验证）**——三步，全部匿名、无验证码、无登录：
1. `GET https://webapi.ctfile.com/getfile.php?path=f&f=<id>&passcode=<p>&ref=&url=<分享页>` → `{"file":{file_id, file_chk, start_time, wait_seconds, verifycode, file_name, file_size, ...}}`
2. `GET https://webapi.ctfile.com/get_file_url.php?uid=&fid=&folder_id=0&share_id=&file_chk=&start_time=&wait_seconds=0&mb=0&app=&acheck=0&verifycode=&rd=<rand>` → `{"downurl": "https://165-usw-data.tv002.com/...", "file_size": N}`
3. GET 那个 `downurl` 即可拿字节流。

**必踩故障**：`get_file_url.php` 若不带 **`X-Requested-With: XMLHttpRequest`** 头，会返回 **HTTP 200 + 空 body**（静默拒绝，没有任何错误信息）。加上这个头立刻返回 `code=200` 和 `downurl`。我在这上面卡了三轮。（`other.js` 里的 `getAjaxHeaders()` 对游客返回 `{}`，真正起作用的是 jQuery `dataType:"json"` 自动加的这个头。）另有新接口 `/get_down_url.php`（参数少，`{uid,fid,file_chk,start_time,wait_seconds,rd}`）也能用。

**节流（关键）**：`downurl` 里带 `spd=175000&spd2=16000&threshold=8955759`。实测：**单个响应前 8,955,759 字节（8.54MB）全速 ~1MB/s，越过阈值后恒定 15.6KB/s**。整包 21.35MB 不分块下要 **14 分钟**。
**绕法**：8.54MB 配额是**按响应**算的 → 用 `Range` 分块请求（8MB 一块）。实测三块分别 3217/3198/2026 KB/s，**21.35MB 共 7.8 秒**，快 **107 倍**。城通**支持 Range**（返回 206）。

**数据真实性（已验）**：书包 zip 内条目 = `JiDuChengGong.azw3`(9.25MB) + `JiDuChengGong.epub`(7.06MB) + `JiDuChengGong.mobi`(9.84MB) + `读书派（www.dushupai.com）.url` + `免责声明.txt`。`zipfile.testzip()` 返回 None（CRC 全通过）；azw3/mobi 的 magic60 = `BOOKMOBI`；epub `mimetype=application/epub+zip`、74 个内层条目；正文抽样 `chapter13.xhtml` 标题「极度成功」，内容是《极度成功》原文。**书是真的**。zip 内文件名是**拼音**（无中文名编码问题），zip 本身叫 `<数字ID>.zip`。

**体量（40 条随机抽样，0 失败）**：min 0.58MB / 中位 8.07MB / max 247.59MB / **均值 21.92MB**。据此：全量 zip **242.9 GB**；只留 epub **约 81 GB**；串行 7.8s/本 ≈ **24.6 小时**，含元数据请求 10s/本 ≈ 31.5 小时，4 并发 ≈ 7.9 小时。

**仍未知（未实测）**：规模化（约 5.7 万次请求）后城通是否 IP 频控/封禁/日配额；`downurl` 里 `limit=1` 的确切含义。

**已产出**：`CONTEXT.md` 已重写（新增 书包 / 换链 / 节流阈值 / 去重 等术语；`资源链接` 定义已从"必须人工介入"更正为"可程序化换取直链"）。实测脚本在 `%TEMP%\ctfile_*.py`。

## ⚠️⚠️ 第二轮更正：上文的「并发提速」估算与固定分块假设**都是错的**

上文说「4 并发 ≈ 7.9 小时」「8MB 一块」——实测全部推翻。以下为 2026-09-23 晚的最终结论：

**① `threshold` 逐文件不同，不是固定 8.54MB。** 规律 `threshold = max(1_000_000, file_size × 40%)`。
必须从 `downurl` 查询参数里解析。写死 8MB 的后果：任何 <20MB 的文件超出部分直接掉进 16KB/s
（实测 1.85MB 的书要 60s、6.57MB 的要 278s）。

**② 并发会让整体速度崩掉（最重要）。** 实测同一本 21.35MB 的书：单连接 **8.5s**；2 并发 **35s**；
3~6 并发跑 12 本后整体冻结数分钟。**`workers` 必须为 1。**

**③ 媒体主机按文件批次固定分配，换链换不掉。** 抽样 30 本：`1357030xxx` 及更早的文件 22/30 落在
`89-cucc-data.tv002.com`，`135704xxxx` 之后的落在 `*-usw-data.tv002.com`。同一文件反复调
`get_file_url.php` / `get_down_url.php` 都返回同一台。所以单本必须有死磕上限（超了就放弃留给下一轮），
否则一个坏文件会卡死唯一的 worker。

**④ 真正的限制是「按 IP 累积消耗的突发额度」。** 免费档名义速率是 `spd=175000`（≈171 KB/s），
但额度充足时会给 2.5~3.5 MB/s 的突发。连续下载约 50~100MB 后整体塌到几十~几百 KB/s，静默数分钟
**部分**恢复（不保证）。决定性证据：同一文件 `1357044763.zip` 在同一台 `usw-data` 主机上，
19:07 是 400 KB/s，19:35 变成 42 KB/s——文件没变、主机没变，只有「我们下载了多少」变了。
**结论：免费通道实际上拿不到 248GB 的全量；约 171KB/s 稳态 → 全量要两周量级。**
城通 API 自己就给出了会员对比：同一文件 `free_speed="2 分钟"` vs `vip_speed="4 秒"`（约 30 倍）。

**⑤ 已实现的下载器**：`tools/ctfile_downloader.py` —— 单 worker、逐文件解析 threshold、
流式写入 + 慢块检测（8s 窗口 <256KB 即中断换链）、单本累计 3 次异常即放弃、占空比（上一本偏慢则
REST 120s 等额度回血）、append-only JSONL 断点续传（`data/download-state.jsonl`）、
zip CRC 校验后原子改名。常驻运行用计划任务 `ZhuYeEbookDownload`。

**已产出的清单**：`data/manifest.jsonl`（11,348 书包）、`data/catalog.jsonl`（24,071 条目）、
`app/assets/catalog.json`（11,348 本，1.03MB，666 分类）；生成脚本
`tools/build_manifest.py`、`tools/build_app_catalog.py`。落盘根目录 **`E:\chinabook`**。

## 本机 Flutter 环境（已装好，别再重装）

- SDK：`D:\tools\flutter`（git clone stable，**Flutter 3.47.5 / Dart 3.13.4**）。
- **重要坑**：`flutter.bat` 首次跑会用 **BITS（Start-BitsTransfer）** 下载 Dart SDK，BITS 在本机
  **会永久卡死**（cache 里留下 `BIT*.tmp`，目录 0 字节）。绕法：读 `bin/cache/engine.stamp` 拿
  engine hash，用 **curl** 取
  `https://storage.googleapis.com/flutter_infra_release/flutter/<hash>/dart-sdk-windows-x64.zip`
  （curl 实测 6MB/s，Invoke-WebRequest 只有 25KB/s），解压到 `bin\cache\`，再写
  `bin\cache\engine-dart-sdk.stamp`（内容=engine hash）。
  另注意：若 stamp 缺失时跑 flutter，它会把已解压的 `dart-sdk` 改名为 `dart-sdk.old1` 并新建空目录——
  修法是删掉空目录、把 old1 改回来。
- 工具链齐备：VS2022 Community（含 VC++ 工具集）、Android SDK 在 `D:\Android\android-sdk`
  （platforms 只有 android-31/33，build-tools 32.0.0）、JDK21 在 `F:\asc_workspace\tool\openjdk-21.0.1`、
