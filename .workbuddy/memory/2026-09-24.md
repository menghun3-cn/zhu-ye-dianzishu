## 1. Flutter Windows release 构建打通（关键进展）

产物：`app/build/windows/x64/runner/Release/zhu_ye_reader.exe`（+ flutter_windows.dll / data/app.so / catalog.json）。

踩了三个坑，按顺序：

### 坑 1：`flutter build windows` 卡死在第 1 步「Windows SDK」，13 分钟无进展
- 现象：`[1/1] Windows SDK └─ [1/4] windows-x64-debug/windows-x64-flutter`，`bin/cache/downloads/.../windows-x64-debug/windows-x64-flutter.zip` 停在 0 字节。
- 根因：本机到 `storage.googleapis.com` 的 **TCP 建连要 21 秒**、速率 66~400KB/s 波动，Flutter 自己的 HttpClient 会放弃/重试到死。用 curl 反而能下。
- 修法（绕过 Flutter 的下载器）：curl 下 4 个 zip → 解包到 `bin/cache/artifacts/engine/` → 写 `bin/cache/windows-sdk.stamp`（内容 = engine revision）。
  关键源码依据：`flutter_tools/lib/src/flutter_cache.dart:876 _getWindowsDesktopBinaryDirs()` 给出 4 个 (目标目录, zip 路径)；
  `cache.dart:930 isUpToDate` = 目录存在 + `windows-sdk.stamp` == engineRevision；`cache.dart:1272 if (link.existsSync()) continue;`。
- 实测 release 构建只需要 `windows-x64-release/`（flutter_windows.dll + gen_snapshot.exe）+ `windows-x64/`（cpp wrapper 头文件），
  但 `isUpToDateInner` 要求 4 个目标目录都存在，所以都要在位。
- 详见 skill：`flutter-windows-artifacts-offline`。

### 坑 2：`.plugin_symlinks` 建符号链接失败
- 现象：`PathExistsException: Cannot create link .../ephemeral/.plugin_symlinks/jni`，或 CMake 报
  `add_subdirectory .../jni/windows which is not an existing directory`。
- 根因：**dart:io 建符号链接需要管理员/开发者模式**；本机没有，于是建出一个空目录，Flutter 的
  `Link.existsSync()` 对普通目录返回 false，下一轮又去建 → 崩。
- 修法（本项目的正解）：**彻底去掉 path_provider**。它是唯一平台插件，且
  `path_provider → path_provider_android → jni` 会把 JNI 原生工程塞进 Windows 构建。
  新增 `lib/services/appdirs.dart`（纯 Dart 算 APPDATA/XDG 路径），`pub get` 后一次性移除 22 个包。
  → 现在工程**零平台插件**，三端构建都只剩 Flutter 自己的产物，这条坑再也不会出现。

### 坑 3：构建过程中改源文件
- 教训：build 在跑的时候不要 Edit `lib/`，产物可能是混合版本；改完必须重新 build 一遍再验收。

## 2. 城通下载器：v1 策略被证伪，写了 v2

### v1 实测数据（2026-09-23 19:07~20:18，40 分钟）
- 12 本连续失败，全部同款：`give-up: 3 次限速错误 @45~73% (host=89-cucc-data.tv002.com)`。
- 该进程 40 分钟只搬运了 **2.4MB**（≈1KB/s），ETA 报 7361 小时（307 天）。
- 免费额度模型确认：**爆发期 ~1MB/s（26.4MB/26s），额度只有 ~30-100MB，耗尽后恒定 16KB/s 且持续 1 小时以上**；
  静默 20 分钟只回 ~1-2MB，静默 120s 基本等于没休息。
- v1 的病根：限速后只 `rest 120s`，然后拿这点额度去冲下一本，又在 ~48% 处崩 → 死循环 100% 失败。

### v2（`tools/ctfile_downloader2.py`）
- 限速后进「**长静默 + 低频探测**」：先静默 `--rest-min 900`，之后每 `--probe-interval 300` 发一个
  256KB 的 Range 探测；速率 ≥ `--probe-kbps 500` 才恢复正式下载，最长 `--rest-max 5400`。
- 限速期间**不重新握手**（v1 每次限速都重握手，既招 503 又火上浇油），沿用原 downurl 从 off 续。
- 单本最多 `--max-rest-cycles 4` 轮，超过跳下一本（`.part` 留着）。
- `run_pass` 里把**已有 `.part` 的书排到最前**（半成品最划算，先收尾）。
- 启动参数：`--workers 1 --loop --rest-min 900 --rest-max 5400 --probe-interval 300 --probe-kbps 500 --pack-timeout 1800 --max-rest-cycles 4 --max-attempts 2 --delay 1`
- 首次运行即见效：`09:16:07 OK 1357050910.zip 3.02MB 28s(活跃 27s)`（v1 在这本上失败过 5 次）。

## 4. Flutter Android 构建：Gradle 锁冲突（本项目 Android 交付的关键坑）

### 现象
`java.io.FileNotFoundException: C:\Users\admin\.gradle\caches\9.3.1\transforms\<hash>\<hash>.lock (拒绝访问。)`
堆栈落在 `org.gradle.cache.internal.filelock.LockFileAccess.<init>` → 即 `new RandomAccessFile(lock,"rw")` 被拒。
先后在 3 个阶段复现：settings 插件解析、`:gradle:compileKotlin`、`MergeInstrumentationAnalysisTransform`。

### 诊断过程（避免重复劳动）
- 单独在 `transforms/` 下做 120 次「建目录→建 .lock→ReadWrite+Share(Read,Write) 打开→LockFileEx→删」：**零失败**
  → 不是权限/路径/ACL 问题。
- 失败的那个 transform 目录里 `workspace/transformed/analysis/*.bin`（92KB+85KB）**已经写好了**
  → 说明 transform 本身成功，是**随后再次抢同一个 transform 工作区的锁**时失败。报错原文也是
  `Multiple build operations failed`（同时两个 hash）→ 典型**并发争锁**。
- 关掉沙箱（`dangerouslyDisableSandbox`）能让 `:gradle:compileKotlin` 通过，但仍在 transform 锁上失败 → 沙箱只是加重因素，不是唯一原因。

### 修法（有效）
在 `app/android/gradle.properties` 里串行化 Gradle 工作线程：
```
org.gradle.parallel=false
org.gradle.workers.max=1
```
加上后 **配置阶段一次通过**（`:gradle:jar` UP-TO-DATE、`Configure project :app` 无报错）。
代价只是慢一点，不影响产物。

**坑 A：Android SDK Platform 36 装不上（sdkmanager 解压中断）**

**坑 B：`Copy-Item` / `robocopy` 拷到一半脚本静默终止**
真凶不是权限，是 **native 命令接了管道 + 非零退出码 → NativeCommandError 把整个 PowerShell 脚本终止**
（`robocopy ... | Out-Null` 就是这样，退出码 1 其实是成功）。

`ndk\28.2.13676358\` 只有 `source.properties` + 空目录链（之前那次安装失败只留了个桩），
`toolchains\llvm\prebuilt\windows-x86_64\bin\` **完全是空的**。

**坑 D：`stripReleaseDebugSymbols` 失败 → APK 166.7MB**
Flutter 引擎 `io.flutter:arm64_v8a_release` 里的 `libflutter.so` 是**未 strip** 的 165MB；
strip 后 11.7MB，对应 APK 从 166.7MB → **17.9MB**。
本机没有 NDK 全量包，但 `llvm-strip.exe` 在别处有现成的：
`C:\Program Files\dotnet\packs\Microsoft.Android.Sdk.Windows\33.0.68\tools\binutils\bin\`
（VS 的 Xamarin 目录也有一份，但那条路径被 LOLBin 黑名单拦）。
robocopy 进 NDK 桩 bin 即可。

**坑 E：`extractReleaseNativeSymbolTables` 又要 `llvm-objcopy`**
AGP 9 的 release 默认要提取 native 符号表（走 llvm-objcopy），下个任务接着炸。
→ **LLVM 里 `llvm-strip` 与 `llvm-objcopy` 本来就是同一个二进制**（按 argv[0] 分派行为），
把 `llvm-strip.exe` 复制一份改名成 `llvm-objcopy.exe` 就能用，
`--only-keep-debug` 验证 exit 0、产物 153MB（不进 APK）。加上后构建 success。

**坑 F（教训）：PowerShell 里含 LOLBin 目录路径的命令会被整条拦**

—— `...\MSBuild\Xamarin\Android\binutils\bin` 这种含 as.exe/ld.exe 的目录，
哪怕只做 `[System.IO.File]::Copy` 也拦。换 dotnet 的 binutils 路径即可。

## 8. 用户验收反馈「没有显示正文内容」→ 查出 EPUB 解析的三个真 bug
用户打开 Windows 版后反馈正文空白。写了两个临时诊断工具（保留在 `app/tool/`）：
- `tool/dump_dom.dart <文件>`：把 XHTML 解析后的 DOM 结构打出来（含 localName / namespaceUri / attributes keys）
- `tool/probe_epub.dart <epub|zip>`：对单个 epub 跑真实解析路径，打印每章块数与块类型
另有 `app/test/diagnose_shelf_test.dart`：跑遍 `E:\chinabook` 全库，逐本打印
`章节数 / 非空章节数 / ch0 的 href+rawLen+块数`。**51 本 2 秒跑完**，非常划算。

### 根因（三个叠在一起，全都指向"打开书一片空白"）
1. **calibre 封面页用的是 SVG**：`titlepage.xhtml` 里是
   `<svg><image width=845 height=1351 xlink:href="cover.jpeg"/></svg>`。
   解析器只认 `<img>`，不认 `<image>` → 整页 0 个块 → `paginate([])` 返回 `[[]]`
   （**注意 `paginate` 空输入会补一个空页，所以 UI 不会转圈，而是显示一页纯空白**）。
2. **`package:html` 的 attributes key 对命名空间属性不是字符串**：
   `attributes['xlink:href']` 取不到值（key 是带命名空间的对象，`toString()` 才长得像 `xlink:href`）。
   → 加了 `_attr(el, name)` 辅助：先直接查，再遍历 `attributes.entries` 用
   `key.toString() == name || endsWith(':$name')` 兜底。
3. **`_norm()` 不折叠 `..`**：EPUB 内封面/插图大量写成 `../Images/x.jpg`，
   不折叠就永远找不到文件 → 插图整片丢失。

### 连带修的问题
4. **图片会撑破页面**：`Paginator._imageHeight` 把图片限制在页高 45%，但渲染侧
   `_PageContent` 用全宽 AspectRatio 不限高 → overflow。
   → `_imgMaxFrac` 改公开 `Paginator.imgMaxFrac`，`_PageContent` 加 `maxHeight` 参数，
   外层套 `ConstrainedBox(maxHeight: maxHeight * imgMaxFrac)`。**两边上限必须一致**。
5. **打开书落在封面页**：spine 第 0 章普遍是 titlepage/cover（纯图）。
   → `reader.dart` 新增 `_firstReadableFrom(b, from)`：从 resume 章起找第一个
   **含非图片块**（即有文字）的章节；找不到退回第一个非空章节，再退回 from。
   `_load()` 无条件调用它（不只在"无进度"时），`_gotoChapter()` 也用同样的跳过逻辑。

### A. 键盘快捷键（`reader.dart`）
- `build()` 拆成 `Focus(key:'reader-keys', autofocus, onKeyEvent:_onKey) → _buildScaffold()`。
  **必须在最外层包 Focus**：正文外面套着 SelectionArea，它只处理复制/全选，方向键会沿焦点链

- `_gotoChapter(i, {atEnd})`：**跳过空章的方向要按「相对当前位置」定**（`i < _chapter` 就往前找），
  不能按 `atEnd` 定 —— 否则从第 5 章往回跳遇到第 4 章是空章会被推回第 5 章，等于没动。
